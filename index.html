About Hashing

      

        A cryptographic hash function maps arbitrary data to a fixed-size digest. It is one-way — you cannot reverse a hash to get the original data. Even a single-bit change in the input produces a completely different hash (avalanche effect). Hashes are used for password storage, file integrity verification, digital signatures, and blockchain.
      

    

  


  
  

    

      
AES-256-GCM

      

        Advanced Encryption Standard in Galois/Counter Mode. Symmetric cipher — same key encrypts and decrypts. Each operation generates a random 128-bit salt + 96-bit nonce. The password is stretched via PBKDF2-SHA256 (480,000 iterations) to produce a 256-bit key. GCM mode provides authenticated encryption — tampering is detected.
      

      

      

        
Key size    → 256 bits

        
Mode       → GCM (authenticated)

        
KDF        → PBKDF2-SHA256

        
Salt        → 16 bytes (random)

        
Nonce      → 12 bytes (random)

      

    

    

      
RSA-2048 / OAEP

      

        Rivest–Shamir–Adleman asymmetric encryption. Two mathematically linked keys — public key encrypts, private key decrypts. Uses OAEP padding with SHA-256 for security. Suitable for encrypting small payloads or symmetric keys (hybrid encryption pattern).
      

      

      

        
Key sizes   → 2048 / 4096 bits

        
Padding    → OAEP-SHA256

        
Exponent   → 65537

        
Format     → PEM (PKCS#1)

      

    

    

      
PATENT PENDINGIoT Device Authentication System

      

        A four-component cryptographic architecture for tamper-evident IoT sensor data integrity. Operates fully offline — no cloud, no server, no internet required.
      

      

        

          
① DEVICE IDENTITY REGISTRY

          
Generates an RSA keypair bound to a unique Device ID. Computes a SHA-256 SPKI fingerprint of the public key and issues a locally-signed device certificate.

        

        

          
② DEVICE-BOUND HYBRID ENCRYPTION

          
Encrypts data with AES-256-GCM, passing the target Device ID as Additional Authenticated Data (AAD). The AES key is wrapped with RSA-OAEP. Decryption is ACCESS DENIED if the requesting device ID does not match the embedded target ID.

        

        

          
③ DETERMINISTIC BLOCK HASHING LEDGER

          
Each sensor reading is stored as a hash-linked block. The block hash is computed by serializing fields with sorted keys (excluding hash/signature to avoid circular references), then signed with the device private key via RSA-PSS.

        

        

          
④ FORENSIC AUDIT ENGINE

          
Performs an O(N) linear scan: verifies index continuity, recomputes each block SHA-256 hash, validates the chronological prev_hash link, and verifies the RSA-PSS signature — detecting any tampering instantly.

        

      

      

      

        
Ledger hash     → SHA-256 (sorted-key canonical JSON)

        
Signatures      → RSA-PSS / SHA-256

        
Encryption      → RSA-OAEP + AES-256-GCM + Device AAD

        
Deployment      → Fully offline / air-gapped capable
